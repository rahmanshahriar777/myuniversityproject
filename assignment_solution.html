Question 2: Test Case Design (10 Marks)

Application Scenario: Testing an enterprise Authentication / Login System with three core user interface components: Username (text input), Password (masked text input), and Login Button (submission trigger).

Functional Requirements (FR) Specification:
  • FR-01: Username must not be empty.
  • FR-02: Password must be at least 6 characters long.
  • FR-03: Valid username and password allow a successful login.
  • FR-04: Invalid credentials should display an appropriate error message.
  • FR-05: After 3 consecutive failed login attempts, the account should be locked.

Test Design Techniques Applied:

  • Equivalence Partitioning (EP): Partitioning inputs into valid partitions (non-empty username, password ≥ 6 characters, registered account) and invalid partitions (empty fields, password < 6 characters, unregistered credentials).
  • Boundary Value Analysis (BVA): Evaluating lengths around the 6-character threshold (length = 0, length = 5, length = 6, length = 7).
  • State Transition Testing: Verifying system behavior across failed attempts (Attempt 1 → Attempt 2 → Attempt 3 [Locked] → Attempt on Locked Account → Successful Reset).
  • Security & Error Guessing: Preventing username enumeration by verifying generic messages for unregistered accounts and testing whitespace-only inputs.
